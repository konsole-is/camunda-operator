## Bubble-up log

- **2026-08-15 — `status.storageSize` on ElasticsearchCluster (user, #37):** the smallest capacity that the data PVCs report (ECK label `elasticsearch.k8s.elastic.co/cluster-name`, claim name prefix `elasticsearch-data-`), falling back to the applied ECK claim size until a claim reports one. A PVC watch mapped through that label refreshes it. Rationale: a future auto-resize (PVCAutoResize) grows PVCs directly, not through spec, and consumers and the resizer itself need the observed size. **PVCAutoResize batch:** read this field, do not derive size from spec or the ECK template.
- **2026-08-15 — storageSize shrink is ignored, not refused (user, #37):** a preset baseline lowered under running clusters, or an inline value set below a previously preset-provided size, no longer halts reconciliation with `Ready=False/InvalidReference`. The controller keeps the applied data volume size, records a Warning event `StorageShrinkIgnored`, and continues. Lowering a preset for future clusters is therefore safe for existing ones. Docs for the cluster and preset updated. `make manifests` regenerated nothing: the CEL rule on the inline field is unchanged.
- **2026-08-15 — no separate `Suspended` condition (user, #37):** with `Ready` mirroring the ocf aggregate, a suspended cluster already reports `ElasticsearchReady=True/Suspended` and `Ready=True/Suspended`, and `ElasticsearchReady` carries `PendingSuspension`/`Suspending` on the way. The `Suspended` condition, `ConditionSuspended`, `ReasonSuspended`, and `SuspendedCondition` are removed; TEMPLATE.md now says a suspendable CRD reports suspension on `Ready`, never as a separate condition. **Batch D:** drop the planned `ClusterSuspended`/`ClusterNotSuspended` on CamundaCluster for the same reason. General direction from the user: `docs/` (CRD docs, spec, plan) are guidelines to adjust when the code finds a better shape, not a contract to preserve.
- **2026-08-15 — Ready mirrors the ocf aggregate (user, both consumer branches):** `DeriveReady` and its `Progressing`/`Suspended` flattening are gone. `conditions.Aggregate(componentConds, gen)` mirrors the component condition with the highest `component.Status.Priority()` onto `Ready` — same status, same reason, message names the component; `Unknown` with no components. Pre-check failures become `Ready` directly with the `api/v1` pre-check reasons. `Suspended` is `Ready=True` per ocf (desired state reached); `Suspending` is False. `ReasonProgressing`/`ReasonSuspended` removed from `api/v1/conditions.go`; ES declares `ConditionSuspended`/`ReasonSuspended` in its own types file. CRD doc tables for Database and ElasticsearchCluster rewritten: pre-check rows, then "`Ready` mirrors the representative component condition, reasons are ocf statuses". TEMPLATE.md reason guidance updated. Later batches: no new aggregate reasons; use ocf's.
- **2026-08-15 — condition vocabulary to `api/v1`, `PatchReady` removed (user, both consumer branches):** `api/v1/conditions.go` holds the cross-CRD vocabulary (`ConditionReady`, `ReasonHealthy`, `ReasonProgressing`, `ReasonInvalidReference`, `ReasonMissingSecret`, `ReasonConnectionFailed`, `ReasonSuspended`); a reason that one CRD reports is declared in that CRD's types file (`ConditionSuspended` in `elasticsearchcluster_types.go` on #37). Every CRD type now implements ocf's `OperatorCRD` (`GetStatusConditions`, `GetKind`); the `GetConditions`/`GetObservedGeneration` getters that only `PatchReady` used are gone. `pkg/conditions` is derivation only: `PreCheckFailure`, `DeriveReady`, `Ready`. The five contract validators stage their Ready with `meta.SetStatusCondition` and persist through `component.FlushStatus`, the same single write path as Database and ElasticsearchCluster. CLAUDE.md: SSA is for managed resources; a CR's own status goes through `FlushStatus`. `how-we-write-go` status section rewritten to match. Later batches: put `Completed`, `Failed`, `PitrUnavailable`, `SharedServer`, … in the owning CRD's types file, not in a shared package.
- **2026-08-15 — layout decision, both consumer branches (user, applied on `batch-b/database` and `batch-b/elasticsearchcluster`, uncommitted):** builders and other pure spec-to-resource code leave the controller packages. New homes: `pkg/components/database` (`ResolveBindings`, `BackupUserName`, `BindingsComponent`, `CollisionKey`/`CollisionWinner`, goldens) and `pkg/components/elasticsearchcluster` (`MergePreset`, `ValidateMerged`, `CredentialsComponent`, `ElasticsearchComponent`, `StorageContractComponent`, goldens).
